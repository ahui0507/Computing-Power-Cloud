# 故障复盘：K3s containerd 镜像引用名规范化问题

> **故障级别**：P1（阻塞性问题）  
> **影响范围**：所有使用本地导入镜像的 Pod 创建  
> **状态**：✅ 已完全解决  
> **复盘时间**：2024年

---

## 一、故障现象

### 症状描述

Pod 创建后一直处于 `ErrImageNeverPull` 状态，无法正常启动。

**关键错误信息**：
```
Events:
  Warning  Failed      ErrImageNeverPull  Image: "jupyter-test:latest" is not present with pull policy of Never
```

### 验证场景

- ✅ 镜像已通过 `ctr -n k8s.io images import` 导入
- ✅ containerd 中可看到镜像：`ctr -n k8s.io images ls | grep jupyter-test`
- ✅ 节点状态正常：`kubectl get nodes` 显示 Ready
- ✅ k3s/containerd 服务正常运行
- ✅ `imagePullPolicy: Never` 已正确设置
- ❌ Pod 仍然无法找到镜像

## 三、根因分析（核心结论）

### 唯一根因

> **containerd 中的镜像引用名 ≠ kubelet/CRI 规范化后的镜像名**

| 组件 | 使用的镜像名 | 说明 |
|------|------------|------|
| 导入时 | `jupyter-test:latest` | 用户直接导入的短名称 |
| kubelet/CRI 查找时 | `docker.io/library/jupyter-test:latest` | 自动规范化后的完整名称 |
| containerd 存储 | `jupyter-test:latest` | 只有短名称引用 |

### 技术原理

1. **Kubernetes CRI 规范**：
   - 当 Pod 中指定 `image: jupyter-test:latest` 时
   - kubelet 通过 CRI 接口请求 containerd
   - CRI 会自动将短名称规范化：`jupyter-test:latest` → `docker.io/library/jupyter-test:latest`

2. **containerd 镜像查找机制**：
   - containerd 使用**精确匹配**查找镜像
   - 如果只有 `jupyter-test:latest` 标签
   - 查找 `docker.io/library/jupyter-test:latest` 时会**失败**

3. **imagePullPolicy: Never 的影响**：
   - `Never` 策略的含义：**如果 CRI 找不到完全同名镜像 → 直接失败，不允许 fallback**
   - 因此不会尝试拉取，也不会尝试其他名称变体

### 问题链路图

```
用户操作：
  ctr -n k8s.io images import xxx.tar
  → containerd 存储：jupyter-test:latest

Pod 创建：
  image: jupyter-test:latest
  imagePullPolicy: Never
  → kubelet 接收 PodSpec

CRI 规范化：
  kubelet → containerd (CRI)
  → 查找：docker.io/library/jupyter-test:latest

查找失败：
  containerd 中只有 jupyter-test:latest
  → 找不到 docker.io/library/jupyter-test:latest
  → ErrImageNeverPull
```

## 四、解决方案

### 标准修复流程

在导入镜像后，必须添加规范化标签：

```bash
# 1. 导入镜像
ctr -n k8s.io images import xxx.tar

# 2. 添加规范化标签（关键步骤）
ctr -n k8s.io images tag jupyter-test:latest docker.io/library/jupyter-test:latest

# 3. 验证标签存在
ctr -n k8s.io images ls | grep docker.io/library/jupyter-test

# 4. 重新创建 Pod
kubectl delete pod <pod-name> && kubectl create -f pod.yaml
```

### 验证成功的证据

```bash
kubectl describe pod <pod-name>

# 输出：
Status:        Running
Ready:         True
Image:         jupyter-test:latest
Image ID:      sha256:81ed026887501...
Node:          worker1

Events:
  Normal  Pulled   Container image "jupyter-test:latest" already present on machine
  Normal  Created  Created container
  Normal  Started  Started container
```

### ✅ 镜像导入标准流程（Worker 节点）

**必须遵循的三步法**：

```bash
# 步骤 1: 导入镜像
ctr -n k8s.io images import <image-tar-file>

# 步骤 2: 添加规范化标签（必须）

ctr -n k8s.io images tag ${IMAGE_NAME}:latest docker.io/library/${IMAGE_NAME}:latest

# 步骤 3: 验证标签存在
ctr -n k8s.io images ls | grep docker.io/library/${IMAGE_NAME}
```

### ✅ Pod 模板标准

```yaml
spec:
  containers:
    - name: container
      image: <image-name>:latest  # 可以使用短名称
      imagePullPolicy: Never      # 必须设置为 Never（离线环境）
```

### ✅ 自动校验脚本（平台侧）

**创建 Pod 前必须执行镜像一致性检查**：

```bash
#!/bin/bash
# scripts/verify_image_before_pod_creation.sh

IMAGE_NAME=$1
REQUIRED_TAG="docker.io/library/${IMAGE_NAME}:latest"

# 在所有目标节点上检查
for NODE in $(kubectl get nodes -o name); do
    NODE_NAME=${NODE#node/}
    
    # 检查镜像是否存在（需要通过节点上的 ctr）
    if ! ssh $NODE_NAME "ctr -n k8s.io images ls | grep -q '${REQUIRED_TAG}'"; then
        echo "ERROR: Image ${REQUIRED_TAG} not found on node ${NODE_NAME}"
        echo "Please run: ctr -n k8s.io images tag ${IMAGE_NAME}:latest ${REQUIRED_TAG}"
        exit 1
    fi
done

echo "✅ Image ${REQUIRED_TAG} verified on all target nodes"
```

### ✅ 镜像导入脚本模板

```bash
#!/bin/bash
# scripts/import_image_with_tag.sh

IMAGE_TAR=$1
IMAGE_NAME=$2
IMAGE_TAG=${3:-latest}

# 1. 导入镜像
echo "Importing image..."
ctr -n k8s.io images import ${IMAGE_TAR}

# 2. 添加规范化标签
echo "Tagging image with normalized name..."
ctr -n k8s.io images tag ${IMAGE_NAME}:${IMAGE_TAG} docker.io/library/${IMAGE_NAME}:${IMAGE_TAG}

# 3. 验证
echo "Verifying image..."
if ctr -n k8s.io images ls | grep -q "docker.io/library/${IMAGE_NAME}:${IMAGE_TAG}"; then
    echo "✅ Image imported and tagged successfully"
else
    echo "❌ Failed to verify image tag"
    exit 1
fi
```

## 六、常见误区排除

### ❌ 误区 1：虚拟环境问题

**错误假设**：Python venv 环境影响了 k3s 的镜像识别。

**事实**：
- Python venv 只影响 Web 后端（FastAPI/uvicorn）的运行环境
- k3s/kubelet/containerd 全部是 systemd 管理的 root 进程
- Pod 创建链路与 FastAPI/uvicorn **零交集**

**结论**：可以彻底排除，标记为：
> *"k8s 调度/镜像问题 ≠ 应用运行环境问题"*

### ❌ 误区 2：imagePullPolicy 设置错误

**错误假设**：`IfNotPresent` 应该能自动回退到本地镜像。

**事实**：
- `IfNotPresent` 会先尝试网络拉取
- 离线环境下会超时
- `Never` 是正确的策略，但需要镜像名称匹配

**结论**：策略正确，问题在于镜像名称不匹配。

### ❌ 误区 3：需要重启服务

**错误假设**：重启 k3s 能刷新 containerd 缓存。

**事实**：
- containerd 的镜像存储是持久化的
- 重启不会改变镜像标签
- 只有添加正确的标签才能解决问题

**结论**：重启不是解决方案，添加标签才是。

## 附录：快速参考

### 问题快速判断

| 症状 | 可能原因 | 快速检查 |
|------|---------|---------|
| `ErrImageNeverPull` | 镜像名称不匹配 | `ctr -n k8s.io images ls \| grep docker.io` |
| `ImagePullBackOff` | 网络问题或策略错误 | `kubectl describe pod \| grep imagePullPolicy` |
| Pod Pending | 镜像不存在或资源不足 | `kubectl describe pod` 查看 Events |

### 一键修复脚本

```bash
#!/bin/bash
# fix_image_tag.sh - 修复镜像标签问题

IMAGE_NAME=${1:-jupyter-test}
IMAGE_TAG=${2:-latest}

echo "Fixing image tag for ${IMAGE_NAME}:${IMAGE_TAG}..."

# 查找 ctr 路径
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)

if [ -z "$CTR_PATH" ]; then
    echo "ERROR: ctr not found"
    exit 1
fi

# 检查原始镜像是否存在
if ! sudo $CTR_PATH -n k8s.io images ls | grep -q "${IMAGE_NAME}:${IMAGE_TAG}"; then
    echo "ERROR: Image ${IMAGE_NAME}:${IMAGE_TAG} not found"
    exit 1
fi

# 添加规范化标签
echo "Adding normalized tag..."
sudo $CTR_PATH -n k8s.io images tag ${IMAGE_NAME}:${IMAGE_TAG} docker.io/library/${IMAGE_NAME}:${IMAGE_TAG}

# 验证
if sudo $CTR_PATH -n k8s.io images ls | grep -q "docker.io/library/${IMAGE_NAME}:${IMAGE_TAG}"; then
    echo "✅ Successfully tagged image"
else
    echo "❌ Failed to tag image"
    exit 1
fi
```
