# Jupyter连接故障排查指南

## 问题：连接超时

如果使用 `http://REPLACE_NODE_INTERNAL_IP:32133/` 连接Jupyter时出现连接超时，请按以下步骤排查：

## 1. 使用诊断脚本

首先运行诊断脚本检查Pod和Service状态：

```bash
cd backend
python scripts/diagnose_jupyter_connection.py <container_id>
```

或者诊断所有实例：

```bash
python scripts/diagnose_jupyter_connection.py --all
```

诊断脚本会显示：
- Pod状态和运行节点
- 容器状态
- Service端口配置
- Endpoints状态
- Pod日志

## 2. 手动检查步骤

### 步骤1：检查Pod状态

```bash
# 查看所有Pod
kubectl get pods -n default

# 查看特定Pod的详细信息
kubectl get pod <pod-name> -n default -o wide

# 查看Pod状态
kubectl describe pod <pod-name> -n default

# 检查Pod中的容器定义（使用脚本）
python backend/scripts/check_pod_containers.py <pod-name>
```

**期望结果**：
- Pod状态应该是 `Running`
- 容器状态应该是 `Ready`
- 有节点名称（Node列）
- Pod spec中应该有容器定义（名称：`container`）
- Pod status中应该有容器状态

**如果看不到容器**：
```bash
# 检查Pod的YAML定义
kubectl get pod <pod-name> -n default -o yaml | grep -A 20 "containers:"

# 检查Pod事件
kubectl describe pod <pod-name> -n default | grep -A 10 "Events:"
```

### 步骤2：检查Service状态

```bash
# 查看所有Service
kubectl get svc -n default

# 查看特定Service的详细信息
kubectl get svc <service-name> -n default -o yaml

# 检查Service的Endpoints
kubectl get endpoints <service-name> -n default
```

**期望结果**：
- Service类型应该是 `NodePort`
- Jupyter端口应该有NodePort（30000-32767范围）
- Endpoints中应该有Pod的IP地址

### 步骤3：检查Pod日志

```bash
# 查看Pod日志
kubectl logs <pod-name> -n default

# 实时查看日志
kubectl logs <pod-name> -n default -f
```

**期望结果**：
- 应该看到Jupyter启动日志
- 应该看到类似：`Jupyter Server is running at http://0.0.0.0:8888/`
- 不应该有错误信息

### 步骤4：检查节点IP

```bash
# 查看所有节点
kubectl get nodes -o wide

# 查看Pod运行的节点
kubectl get pod <pod-name> -n default -o jsonpath='{.spec.nodeName}'

# 获取节点IP
NODE_NAME=$(kubectl get pod <pod-name> -n default -o jsonpath='{.spec.nodeName}')
kubectl get node $NODE_NAME -o jsonpath='{.status.addresses[?(@.type=="InternalIP")].address}'
```

**重要**：
- NodePort Service在所有节点上都可以访问
- 但建议使用Pod实际运行的节点IP
- 如果使用其他节点IP，确保该节点可以访问

### 步骤5：检查防火墙

```bash
# 检查防火墙状态（Ubuntu/Debian）
sudo ufw status

# 检查防火墙状态（CentOS/RHEL）
sudo firewall-cmd --list-all

# 如果需要开放端口（示例：32133）
sudo ufw allow 32133/tcp
# 或
sudo firewall-cmd --add-port=32133/tcp --permanent
sudo firewall-cmd --reload
```

### 步骤6：测试端口连通性

```bash
# 从集群内部测试
kubectl run -it --rm debug --image=busybox --restart=Never -- sh
# 在容器内执行：
wget -O- http://<pod-ip>:8888
# 或
telnet <node-ip> 32133

# 从外部测试
curl -v http://<node-ip>:32133
# 或
telnet <node-ip> 32133
```

## 3. 常见问题及解决方案

### 问题1：Pod一直Pending

**原因**：
- 镜像不存在
- 资源不足
- 节点选择器不匹配

**解决方案**：
```bash
# 检查Pod事件
kubectl describe pod <pod-name> -n default

# 检查镜像是否存在
kubectl get pod <pod-name> -n default -o jsonpath='{.spec.containers[0].image}'
ctr images ls | grep jupyter-test

# 如果镜像不存在，导入镜像
cd test-images/jupyter-test
sudo ./build_and_import.sh
```

### 问题2：Pod运行但容器未就绪

**原因**：
- Jupyter启动失败
- 端口配置错误

**解决方案**：
```bash
# 查看容器日志
kubectl logs <pod-name> -n default

# 进入容器检查
kubectl exec -it <pod-name> -n default -- sh
# 在容器内：
ps aux | grep jupyter
netstat -tlnp | grep 8888
```

### 问题3：Service无Endpoints

**原因**：
- Pod标签与Service选择器不匹配
- Pod未就绪

**解决方案**：
```bash
# 检查Pod标签
kubectl get pod <pod-name> -n default --show-labels

# 检查Service选择器
kubectl get svc <service-name> -n default -o jsonpath='{.spec.selector}'

# 确保标签匹配
```

### 问题4：端口无法访问

**原因**：
- 防火墙阻止
- 节点IP错误
- 网络策略限制

**解决方案**：
1. 检查防火墙（见步骤5）
2. 确认使用正确的节点IP（见步骤4）
3. 检查网络策略：
```bash
kubectl get networkpolicies -n default
```

### 问题5：Jupyter未启动

**原因**：
- Dockerfile CMD被覆盖
- 启动命令错误

**解决方案**：
```bash
# 检查Pod的启动命令
kubectl get pod <pod-name> -n default -o jsonpath='{.spec.containers[0].command}'

# 如果命令为空，检查镜像的CMD
docker inspect jupyter-test:latest | grep -A 5 Cmd

# 手动启动Jupyter（进入容器）
kubectl exec -it <pod-name> -n default -- jupyter lab --ip=0.0.0.0 --port=8888 --no-browser --allow-root
```

## 4. 快速修复命令

如果诊断发现问题，可以使用以下命令快速修复：

```bash
# 重新创建Pod（删除并重新申请资源）
# 在网页中释放资源，然后重新申请

# 或者手动删除并重新创建
kubectl delete pod <pod-name> -n default
kubectl delete svc <service-name> -n default
# 然后在网页中重新申请资源
```

## 5. 验证连接

修复后，验证连接：

```bash
# 1. 确认Pod运行
kubectl get pod <pod-name> -n default

# 2. 确认Service有Endpoints
kubectl get endpoints <service-name> -n default

# 3. 确认Jupyter日志
kubectl logs <pod-name> -n default | grep -i jupyter

# 4. 测试连接
curl -I http://<node-ip>:<jupyter-port>
```

## 6. 获取正确的访问地址

访问地址格式：`http://<节点IP>:<Jupyter端口>`

**获取节点IP**：
1. 从"我的实例"页面查看（推荐）
2. 或使用kubectl：
```bash
NODE_NAME=$(kubectl get pod <pod-name> -n default -o jsonpath='{.spec.nodeName}')
kubectl get node $NODE_NAME -o jsonpath='{.status.addresses[?(@.type=="InternalIP")].address}'
```

**获取Jupyter端口**：
1. 从"我的实例"页面查看
2. 或使用kubectl：
```bash
kubectl get svc <service-name> -n default -o jsonpath='{.spec.ports[?(@.name=="jupyter")].nodePort}'
```

## 7. Jupyter 无法访问的专门排查

如果 Pod 运行正常但 JupyterLab 无法访问，请参考：

- **[Jupyter访问故障排查.md](./Jupyter访问故障排查.md)** - 详细的问题诊断和解决方案

常见原因：
1. Jupyter 只监听 `127.0.0.1:8888` 而不是 `0.0.0.0:8888`
2. 没有 Service 或 Service 未分配 NodePort
3. 防火墙阻止了端口访问

快速诊断：
```bash
cd backend
python scripts/diagnose_jupyter_access.py <pod-name>
```
