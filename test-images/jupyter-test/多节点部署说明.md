# 多节点K3s集群镜像部署说明

## 问题

在多节点K3s集群中，如果Pod被调度到不同的节点，需要确保镜像在每个节点上都已导入。

## 解决方案

### 方法1：在每个节点上手动导入（推荐）

在每个节点上运行导入脚本：

```bash
# 在control节点上导出镜像
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
sudo $CTR_PATH images export /tmp/jupyter-test.tar jupyter-test:latest

# 复制到其他节点
scp /tmp/jupyter-test.tar worker1:/tmp/

# 在每个worker节点上导入
ssh worker1
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
sudo $CTR_PATH images import /tmp/jupyter-test.tar
sudo $CTR_PATH images tag docker.io/library/jupyter-test:latest jupyter-test:latest
```

### 方法2：使用同步脚本

```bash
cd backend
chmod +x scripts/sync_image_to_all_nodes.sh
sudo ./scripts/sync_image_to_all_nodes.sh
```

### 方法3：配置私有镜像仓库（生产环境推荐）

配置K3s使用私有镜像仓库，这样所有节点都可以从仓库拉取镜像：

1. 设置镜像仓库地址
2. 配置镜像拉取策略
3. 所有节点自动从仓库获取镜像

## 验证

检查每个节点上的镜像：

```bash
# 在control节点
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
sudo $CTR_PATH images ls | grep jupyter-test

# 在worker1节点
ssh worker1
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
sudo $CTR_PATH images ls | grep jupyter-test
```

## 预防措施

1. **在导入脚本中添加多节点支持**：
   修改 `build_and_import.sh`，自动检测节点并同步镜像

2. **使用DaemonSet部署镜像同步工具**：
   创建一个DaemonSet，自动在所有节点上同步镜像

3. **配置镜像仓库**：
   使用Harbor、Docker Registry等私有仓库，所有节点统一从仓库拉取
