# Jupyter测试镜像使用说明

## 概述

已创建一个简单的Jupyter测试镜像，用于测试Pod创建和Jupyter连接功能，**无需联网拉取镜像**。

## 已创建的文件

1. **Dockerfile** - Jupyter测试镜像定义
2. **build_and_import.sh** - 自动构建和导入脚本
3. **add_to_database.py** - 将镜像添加到数据库的脚本
4. **README.md** - 详细说明文档
5. **QUICK_START.md** - 快速开始指南

## 快速使用步骤

### 情况A: 已用Docker构建好镜像（推荐）

如果你已经在有Docker的机器上构建好了镜像，直接导入：

```bash
cd test-images/jupyter-test
chmod +x import_existing_docker_image.sh
sudo ./import_existing_docker_image.sh jupyter-test latest
```

或者使用更新后的 `build_and_import.sh`（会自动检测已存在的镜像）：

```bash
cd test-images/jupyter-test
chmod +x build_and_import.sh
sudo ./build_and_import.sh
# 脚本会自动检测Docker中是否已有镜像，如果有会询问是否直接导入
```

### 情况B: 需要构建镜像

```bash
cd test-images/jupyter-test
chmod +x build_and_import.sh
sudo ./build_and_import.sh
```

这个脚本会：
- 使用Docker构建镜像
- 导出为tar文件
- 导入到K3s的containerd
- 标记镜像

### 2. 验证镜像已导入

```bash
# 查找ctr命令
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)

# 验证镜像
sudo $CTR_PATH images ls | grep jupyter-test
```

### 3. 添加到数据库

```bash
cd backend
python ../test-images/jupyter-test/add_to_database.py
```

或者手动执行SQL：

```sql
INSERT INTO images (name, tag, description, visibility, created_at)
VALUES ('jupyter-test', 'latest', 'Jupyter测试镜像', 'public', NOW());
```

### 4. 测试创建Pod

1. 在网页中申请资源
2. 选择镜像: `jupyter-test:latest`
3. 选择资源池和GPU数量
4. 提交申请

### 5. 访问Jupyter

1. 等待Pod状态变为Running
2. 在"我的实例"页面查看Jupyter端口（通常是30000-32767之间的端口）
3. 访问: `http://<节点IP>:<jupyter_port>`

**重要提示**：
- 节点IP可以从"我的实例"页面查看
- 如果连接超时，请运行诊断脚本：`python backend/scripts/diagnose_jupyter_connection.py <container_id>`
- 详细故障排查请参考：[故障排查指南](./故障排查指南.md)

## 离线环境使用

如果服务器完全离线，可以在有网络的机器上构建，然后传输：

```bash
# 在有网络的机器上
cd test-images/jupyter-test
docker build -t jupyter-test:latest .
docker save jupyter-test:latest -o jupyter-test.tar

# 传输到目标服务器
scp jupyter-test.tar user@target-server:/tmp/

# 在目标服务器上导入
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
sudo $CTR_PATH images import /tmp/jupyter-test.tar
sudo $CTR_PATH images tag docker.io/jupyter-test:latest jupyter-test:latest
```

## 常见问题

**Q: Pod创建后一直Pending？**
- 检查镜像是否已导入: `sudo ctr images ls | grep jupyter-test`
- 检查节点资源是否充足

**Q: Jupyter无法访问？**
- 运行诊断脚本: `python backend/scripts/diagnose_jupyter_connection.py <container_id>`
- 检查Pod日志: `kubectl logs <pod-name>`
- 检查Service: `kubectl get svc`
- 检查防火墙是否允许NodePort端口访问
- 查看详细的[故障排查指南](./故障排查指南.md)

**Q: 镜像导入失败？**
- 确保使用sudo权限
- 检查ctr路径是否正确: `sudo find /var/lib/rancher -name ctr`

## 镜像特点

- **轻量级**: 基于Python 3.11-slim，体积约200-300MB
- **预配置**: Jupyter已配置为允许所有IP访问，适合K8s NodePort
- **即用**: 包含示例notebook，开箱即用
- **测试专用**: 无密码和token，仅用于测试环境

## 注意事项

1. 此镜像仅用于测试，生产环境请使用更安全的配置
2. 如果需要在多节点使用，需要在每个节点导入镜像
3. 或者配置K3s使用私有镜像仓库统一管理镜像
