# Windows PowerShell：一次实例密码登录

**历史归档：用户已要求恢复两次实例密码方案，本方案现已停用。当前请使用网页提供的 `ssh -J ...` 命令，两次输入同一个实例密码。**

本站已启用按用户与实例授权的 SSH 转发，复用 `http://10.72.63.42:64022/` 的网站入口。所有有效用户均使用自己的实例连接信息，不需要控制节点管理密码、个人 SSH 密钥、Python 或管理员权限。

## 使用方法

1. 刷新网站，在“我的实例 → SSH”点击“刷新连接信息”。
2. 复制整条连接命令，粘贴到 Windows PowerShell 执行。
3. 首次连接核对并确认实例主机指纹，随后只输入一次弹窗中的“实例密码”。

当前命令是自动启动连接的 PowerShell 脚本，调用 Windows 自带的 `ssh.exe`。旧的 `ssh -J ...` 命令仍使用两次认证；需要重新复制网页中的新命令。命令中的转发凭据有效期为 24 小时，过期后刷新连接信息即可；实例密码保持不变。

## 转发与权限

网页后端签发 `ssh-relay` 用途的短期凭据，绑定平台用户、实例分配 ID、容器 ID 与有效期。凭据不能调用其他平台 API，也不能选择任意目标地址。WebSocket 入口再次检查用户有效状态、实例归属、运行状态、Pod 标签，连接该实例的 SSH 服务。最终密码认证由实例 SSH 服务完成。

PowerShell 用系统自带的 .NET 编译通用转发程序，按源码版本缓存到 `%LOCALAPPDATA%\CPCloud\SSH\relay-版本.exe`。缓存程序不包含密码、令牌或密钥。每次连接仅在本机回环地址随机监听一个临时端口，接收一个本机 SSH 连接；SSH 结束后关闭转发进程。SSH 主机指纹使用稳定的实例别名，避免随机端口导致重复指纹确认。

Windows OpenSSH 的 ProxyCommand 标准输入在现场发生握手停滞，因此最终采用本机 TCP 连接传递二进制数据。Windows 实际终端、隐藏测试进程均已验证。当前网页命令打开 SSH 终端；SFTP 的传输验证使用相同转发和 Windows 原生 `sftp.exe`，并非直接将 SSH 命令作为 SFTP 命令。尚未提供 VS Code Remote SSH 的配置导出，弹窗不再宣称已提供该使用流程。

运行中每 15 秒检查用户和实例生命周期；实例释放、用户停用或删除后关闭连接。短期凭据的到期限制作用于建立连接，已建立的会话继续受生命周期检查约束。重启后端会断开经过该后端的转发会话，用户重新运行连接命令即可。

控制节点 SSH 认证和管理账号保持原配置。原带认证的实例专用跳板及回收 timer 作为回退保留；此前被自动审核拒绝的免认证第一跳未重新启用。

## 配置与回退

```dotenv
SSH_RELAY_ENABLED=true
SSH_RELAY_PUBLIC_URL=http://10.72.63.42:64022
SSH_RELAY_TICKET_MINUTES=1440
```

配置位置为控制节点 `/etc/cpcloud/backend.env`。设置 `SSH_RELAY_ENABLED=false` 并重启 `computing-platform-backend`，即可恢复原实例专用带认证跳板。不要修改现有主机 SSH 密码或禁用其认证。备份与验证记录保存在 `/home/system/cpcloud-operations/feedback-20261016/scoped-ssh-relay/`。
