# 镜像导入指南

本指南说明如何将镜像压缩包（tar格式）导入到K3s集群节点中。

## 快速开始

### 方法1: 使用导入脚本（推荐）

```bash
# 导入到当前节点
sudo bash scripts/import_image.sh /path/to/your-image.tar

# 导入并指定镜像名称和标签
sudo bash scripts/import_image.sh /path/to/your-image.tar myimage:latest

# 导入并同步到所有节点
sudo bash scripts/import_image.sh /path/to/your-image.tar myimage:latest --sync-all
```

### 方法2: 手动导入

如果脚本不可用，可以手动执行以下步骤：

#### 步骤1: 查找ctr命令

```bash
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
echo $CTR_PATH
```

#### 步骤2: 导入镜像

```bash
# 导入镜像（使用步骤1找到的CTR_PATH）
sudo $CTR_PATH -n k8s.io images import /path/to/your-image.tar
```

#### 步骤3: 标记镜像（可选）

```bash
# 标记镜像，使其易于识别
sudo $CTR_PATH -n k8s.io images tag docker.io/myimage:latest myimage:latest
```

#### 步骤4: 验证镜像

```bash
# 查看已导入的镜像
sudo $CTR_PATH -n k8s.io images ls | grep myimage
```

## 详细说明

### 导入脚本参数

`scripts/import_image.sh` 脚本支持以下参数：

1. **镜像tar文件路径**（必需）
   - 镜像压缩包的完整路径
   - 例如: `/tmp/myimage.tar`

2. **镜像名称:标签**（可选）
   - 指定镜像的名称和标签
   - 例如: `myimage:latest`、`jupyter-test:v1.0`
   - 如果不指定，脚本会导入镜像但不会自动标记

3. **--sync-all**（可选）
   - 如果指定此参数，脚本会自动将镜像同步到集群中的所有节点
   - 需要SSH访问权限

### 使用示例

#### 示例1: 基本导入

```bash
# 假设你有一个名为 jupyter-test.tar 的镜像文件
sudo bash scripts/import_image.sh /tmp/jupyter-test.tar jupyter-test:latest
```

#### 示例2: 导入并同步到所有节点

```bash
# 导入镜像并自动同步到所有worker节点
sudo bash scripts/import_image.sh /tmp/jupyter-test.tar jupyter-test:latest --sync-all
```

#### 示例3: 仅导入不标记

```bash
# 如果不知道镜像的确切名称，可以先导入查看
sudo bash scripts/import_image.sh /tmp/unknown-image.tar

# 然后查看导入的镜像
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
sudo $CTR_PATH -n k8s.io images ls
```

### 多节点集群

如果你的K3s集群有多个节点，需要在**每个节点**上都导入镜像，或者使用 `--sync-all` 参数自动同步。

#### 手动同步到其他节点

如果自动同步失败，可以手动执行：

```bash
# 1. 复制镜像文件到目标节点
scp /path/to/your-image.tar user@node-ip:/tmp/

# 2. SSH到目标节点
ssh user@node-ip

# 3. 在目标节点上导入
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
sudo $CTR_PATH -n k8s.io images import /tmp/your-image.tar
sudo $CTR_PATH -n k8s.io images tag docker.io/myimage:latest myimage:latest
```

### 验证镜像

导入后，验证镜像是否可用：

```bash
# 查找ctr命令
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)

# 列出所有镜像
sudo $CTR_PATH -n k8s.io images ls

# 搜索特定镜像
sudo $CTR_PATH -n k8s.io images ls | grep myimage
```

### 添加到数据库

导入镜像后，如果需要在系统中使用，可能需要将其添加到数据库。

#### 方法1: 自动同步所有镜像（推荐）

使用 `sync_images_from_node.py` 脚本自动扫描节点中的所有镜像并同步到数据库：

```bash
# 进入backend目录
cd backend

# 同步所有镜像到数据库
python scripts/sync_images_from_node.py

# 仅查看，不实际添加（预览模式）
python scripts/sync_images_from_node.py --dry-run

# 只同步包含特定名称的镜像
python scripts/sync_images_from_node.py --filter "jupyter"

# 添加为私有镜像
python scripts/sync_images_from_node.py --visibility private --owner-id 1
```

这个脚本会：
- 自动扫描当前K3s节点中的所有镜像
- 解析镜像名称和标签
- 获取镜像大小
- 检查数据库中是否已存在
- 自动添加新镜像或更新已有镜像的信息

#### 方法2: 手动添加单个镜像

如果只需要添加特定镜像，可以使用SQL：

```bash
mysql -u root -p computing_platform -e "INSERT INTO images (name, tag, description, visibility, size, created_at) VALUES ('myimage', 'latest', '我的镜像描述', 'public', 2.5, NOW());"
```

或者使用Python交互式：

```bash
cd backend
python
```

```python
from app.core.database import SessionLocal
from app.models.image import Image, ImageVisibility

db = SessionLocal()
image = Image(
    name="myimage",
    tag="latest",
    desc="我的镜像描述",
    visibility=ImageVisibility.PUBLIC,
    size=2.5
)
db.add(image)
db.commit()
print(f"✓ 镜像已添加，ID: {image.id}")
db.close()
```

## 常见问题

### Q1: 找不到ctr命令？

```bash
# 查找ctr命令
sudo find /var/lib/rancher -name ctr

# 通常路径是：
# /var/lib/rancher/k3s/data/current/bin/ctr
```

### Q2: 导入失败？

可能的原因：
- 镜像文件损坏或不完整
- containerd服务未运行
- 权限不足（需要使用sudo）

检查方法：
```bash
# 检查containerd状态
sudo systemctl status containerd
# 或
sudo systemctl status k3s

# 检查镜像文件
file /path/to/your-image.tar
```

### Q3: 镜像导入后看不到？

```bash
# 使用完整命名空间查看
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)
sudo $CTR_PATH -n k8s.io images ls

# 检查镜像标签
sudo $CTR_PATH -n k8s.io images ls | grep -i your-image-name
```

### Q4: 如何从Docker导出镜像？

如果你有Docker环境，可以这样导出：

```bash
# 导出镜像为tar文件
docker save myimage:latest -o myimage.tar

# 然后使用导入脚本导入到K3s
sudo bash scripts/import_image.sh myimage.tar myimage:latest
```

### Q5: 如何删除已导入的镜像？

```bash
CTR_PATH=$(sudo find /var/lib/rancher -name ctr 2>/dev/null | head -1)

# 删除镜像
sudo $CTR_PATH -n k8s.io images rm myimage:latest
```

## 注意事项

1. **权限要求**: 所有导入操作都需要sudo权限
2. **命名空间**: K3s使用 `k8s.io` 命名空间，导入时需要使用 `-n k8s.io` 参数
3. **镜像标签**: 建议为镜像指定明确的名称和标签，便于后续使用
4. **多节点**: 在多节点集群中，确保所有节点都有相同的镜像
5. **存储空间**: 大型镜像会占用较多存储空间，注意磁盘容量
