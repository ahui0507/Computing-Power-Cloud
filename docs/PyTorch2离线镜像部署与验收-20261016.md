## 离线构建

实际使用 [Dockerfile.pytorch2-offline](../deploy/workbench/Dockerfile.pytorch2-offline) 和 [构建脚本](../deploy/workbench/build-pytorch2-offline.sh)。上下文包含offline-debs、wheels、锁文件、验证器与SHA256SUMS；校验清单明确使用LF换行。

```bash
sh /离线上下文/build-pytorch2-offline.sh /离线上下文 campus-workbench:pytorch2-20261016
```

脚本首先核对本地基础镜像config摘要，构建设置 `--pull=false --network none`。APT从上传的本地DEB安装，pip使用 `--no-index --find-links --require-hashes`。镜像最终执行pip check、工具检查、CPU运算与NumPy互操作检查。

初次尝试中发现Windows清单换行、APT `--no-download` 与本地DEB安装的兼容问题，均已修正。基础镜像自带的Ninja 1.11.1.1存在不匹配的平台标签，最终显式固定并离线安装Ninja 1.13.0；没有跳过pip check。最终构建全部通过，镜像逻辑大小6,998,070,590字节，目录显示约7.00 GB；共享层和实际磁盘增量不是同一个数值。
