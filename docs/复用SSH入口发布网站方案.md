# 复用 SSH 入口发布网站方案（待确认，未实施）

目的：无法修改网关时，在控制节点上复用已存在的 TCP 入口，让 `10.240.0.0/16` 用户用浏览器访问统一网站，无需个人 SSH 隧道。

## 已核实的条件

- 控制节点 SSH 入口为 `10.72.63.42:64022`，实际主机为 `192.168.24.64:22`。
- 从当前电脑经该入口收到控制节点 OpenSSH banner；随后发送 HTTP 请求得到 `Invalid SSH identification string`，且节点日志记录相同来源端口的协议拒绝。说明这次 HTTP 数据到达控制节点，并非仅凭 TCP 端口连通推断。
- 节点看到本机原始来源 `10.240.52.192`，WLAN 实际前缀 /16。
- OpenSSH 的 service/socket 均启用；service 为 `KillMode=process`，可设计保留已建立会话的监听切换。是否最终保留全部会话须在切换中验证。
- `127.0.0.1:2222`、`127.0.0.1:8081` 当前未被占用。
- Nginx 已编译 http_realip 模块，具备读取可信 PROXY protocol 元数据的能力。
- HAProxy 尚未安装，发行版候选版本为 3.2.9。下述配置为待验证草案，未宣称已通过 HAProxy 二进制语法检查或正式入口验收。

## 推荐结构

```text
用户浏览器：http://10.72.63.42:64022/
管理员 SSH：ssh -p 64022 system@10.72.63.42
                 |
          现有网关 TCP 映射保持原样
                 |
       控制节点 HAProxy，监听 TCP 22
          |                       |
       HTTP 请求                SSH 协议
          |                       |
 Nginx 127.0.0.1:8081       sshd 127.0.0.1:2222
          |
   前端静态文件 + 现有后端 API
```

HAProxy 根据连接首部区分 HTTP 和 SSH。外部 SSH 地址、端口、用户名、密码和主机密钥保持现值；调整的是控制节点内部监听。浏览器使用普通 HTTP，复用现有可达 TCP 入口，不需要新的网关映射或远端服务器。HTTPS 不在本次草案范围内。

平台仍使用当前 Nginx、FastAPI、MySQL、Redis 和数据卷，不调整计算节点、不重启主机、不停止已有 GPU 容器。

## 网段限制

HAProxy 对 HTTP 连接按实际 TCP 来源只允许 `10.240.0.0/16`，其他来源的 HTTP 连接直接拒绝；SSH 的原有访问范围保持。HTTP 后端通过 PROXY v2 将真实来源送给仅绑定 loopback 的专用 Nginx 监听；该监听仅信任 loopback 的代理元数据，并再次执行相同网段限制。普通请求头 X-Forwarded-For 不能决定访问权限。

现有 `127.0.0.1:8080` 管理和健康检查入口保留，不作为普通用户发布入口。外部用户不能直接连接 PROXY protocol 内部端口。

## 执行与回退步骤

1. 核对 SSH 按来源限制和现有会话，备份 SSH/Nginx 配置、systemd service/socket 启用状态；保持现有管理员连接。
2. 获准后安装 HAProxy，校验配置。在不占用 TCP 22 的临时端口预演 HTTP/SSH 分流、PROXY 元数据和网段限制，验证原账号及主机密钥。
3. 准备回退脚本，并在关键切换前启动独立的 5 分钟自动回退 timer。回退恢复原 SSH 22 监听及原服务/socket 状态，停用新协议入口；不删除平台数据或改变账号密码。
4. 校验 sshd 内部监听配置和 Nginx，切换控制节点 TCP 22 给 HAProxy。切换期间新的 SSH/网页连接可能短暂不可用，不能承诺零影响。现有连接按进程保留设计处理。
5. 从当前电脑建立全新的外部 SSH 登录，确认 host key/命令/账号不变；访问实际统一网址，验证首页、资源、管理员/普通用户登录和 API。
6. 验证非允许来源的 HTTP 请求被拒绝、伪造来源头无法绕过。全部关键检查通过后才取消自动回退并持久化启动顺序；失败或无法复连时由 timer 恢复原入口。

SSH 经过 TCP 代理后，sshd 会看到 loopback 来源，真实 TCP 来源由 HAProxy 日志保留；实施前必须核对现有来源约束，避免改变已配置的公钥来源限制或封禁规则。网站只允许指定网段，不能把代理到 loopback 当作放行全部用户的理由。

## 需要用户批准的具体变更

新增 HAProxy 协议代理；控制节点内部 SSH 监听从 TCP 22 改为 loopback TCP 2222；增加专用 Nginx PROXY protocol 内部监听和自动回退流程。外部 `64022` 登录命令保持，计算节点 `63022` 入口不变。

这涉及新增组件及 SSH 入口路径调整。用户最初要求“涉及架构调整、替换核心组件、改变功能行为或新增功能时，先提出具体方案，等待我确认”，所以本轮只完成只读核实和草案准备，尚未安装 HAProxy 或切换 SSH。
