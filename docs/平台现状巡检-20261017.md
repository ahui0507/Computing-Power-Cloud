依据：当前源码、线上网站/健康/镜像接口、维护状态及 Kubernetes 只读配置。

当前观察：平台 healthy，8/8 张 GPU 可用；存储配额为 filesystem 强制执行；PyTorch 与 TensorFlow 开发镜像已完成 A100 双卡功能验收。下面的问题主要涉及运行保障、多租户隔离和使用流程。

## 优先处理

### 1. 网站 HTTPS（已部署）

网站已启用 `https://10.72.63.42:64022/`，HTTP 自动跳转 HTTPS。TLS 在控制节点 Nginx 终止，`PUBLIC_HTTPS_ENABLED=true`；集群内部 `INGRESS_USE_TLS=false` 保留原路由。HTTPS 登录、Jupyter/WSS、原生 SSH/SFTP 均已实测通过。

按用户选择采用内部 CA 签发的内网 IP 证书，需为每台客户端建立信任；Windows 安装包提供指纹校验、交互式安装和撤销。网站证书自动续期已验证，记录见 [HTTPS 部署与验收](HTTPS部署与验收-20261017.md)。

### 2. 自动异机备份未配置

线上维护状态为 `backup.state=not_configured`，系统 timer 中仅发现系统自带的 dpkg 数据库备份，没有平台备份定时任务。已有发布时的数据库导出和恢复库验证记录，不能覆盖持续更新的用户模型、数据、个人镜像和整站配置。

建议：落实数据库、用户持久目录及镜像/配置元数据的定期异机备份，定义保留周期，并验证完整恢复流程。平台密钥应纳入受保护的恢复材料。

### 3. 租户隔离（已完成本轮加固）

新实例已切换到 `platform-workloads`，采用默认拒绝的 NetworkPolicy、专用且禁止挂载集群凭据的 ServiceAccount，以及受限 capability、禁止提权和 RuntimeDefault seccomp。两个节点另加 IPv6 Pod 网桥 guard，封堵实测发现的链路本地旁路。

已用两个普通账号验证跨用户文件、符号链接、实例及私有镜像访问边界，同时验证管理内网、NFS、实例 Pod/Service/NodePort 与 IPv6 访问阻断。TensorFlow/PyTorch 双卡训练与恢复、Jupyter/WSS、SSH/SFTP、软件安装、个人镜像保存恢复和硬配额均通过；351 项后端回归通过。

记录：[租户隔离加固与验收](租户隔离加固与验收-20261017.md)。这仍是共享内核的容器级加固，NFS AUTH_SYS 与共享 UID/GID 未替换；扩大到完全互不信任的外部租户前，继续评估 GPU 虚拟机、独立节点和存储身份认证。

TensorFlow 环境检查与训练入口均已适配，完成线上 API、浏览器、A100 单卡/双卡和断点恢复验收。多卡示例采用每卡独立进程的 MultiWorkerMirroredStrategy，以避开实测发现的单进程 GPU 间复制异常；通用 P2P 问题仍需专项处理。

### 5. 镜像目录有重复选择与版本辨识问题

线上公共目录有 4 条：TensorFlow 开发版、PyTorch 开发版、旧 PyTorch runtime、显示名称仅为 PyTorch 的旧版。它们属于两类框架，但当前展示没有统一为框架与版本选择。

建议：推荐位展示两套开发环境，旧版收进版本列表；明确 Python/CUDA/框架版本与是否包含 nvcc，保留旧实例和个人镜像引用。

### 6. 释放前任务检查覆盖不完整

目前检查平台登记的后台任务与镜像保存状态。SSH、Jupyter、tmux/nohup 或用户自行启动的程序不会全部进入平台任务登记。现有文档说明了这一限制。

建议：界面持续明确检查范围，并补充当前进程/Notebook 会话的可见性和终止提醒；训练恢复依靠用户程序的 checkpoint 机制。

## 运行保障与验收缺口

### 7. 控制面单点，健康接口覆盖有限

集群目前只有一个控制节点 dell 和一个计算节点 ubuntu。当前健康接口检查数据库版本、表和初始化角色；它不代表调度后台、自动释放、GPU 通信、存储和备份全部健康。定时释放依赖后台服务执行，后端中断期间无法按时实际回收。

建议：先增加调度/释放后台心跳、外部故障通知和恢复演练，再按可用性目标规划控制面冗余。备份与恢复能力优先于单纯增加副本数。

### 8. 长时、多卡性能和真实费用场景仍需专项复核

本轮两个新镜像完成的是短时双卡功能验收；现有压力测试资料也明确十分钟验证的边界。当前 NCCL 使用兼容通信路径，硬件 P2P/ACS/IOMMU 优化尚未完成。由此不能推导八卡长时稳定性、通信效率或所有模型的表现。

本轮镜像验收使用零费率订单，未覆盖有偿长时扣费。计费已有单元与历史部署测试，仍建议结合余额耗尽、服务中断、延迟清理、个人镜像保存/恢复与跨释放文件持久化做专项演练。

建议顺序：自动异机备份；同时优化镜像展示；随后处理通用 GPU P2P 复制问题，并做长时负载与故障恢复验收。HTTPS、TensorFlow 示例与本轮租户隔离加固已完成；扩大到不可信外部用户前仍需升级隔离级别。
