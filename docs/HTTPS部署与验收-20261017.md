## 首次使用

本平台使用内部 CA 签发的 IP 证书。每台电脑、不同 Windows 用户或独立浏览器证书库需要分别建立信任。

1. 从本次交付文件取得 `output/https/CPCloud-HTTPS-Trust.zip`，或访问 `http://10.72.63.42:64022/tls-bootstrap/` 获取公开安装包。
2. 核对下方 CA 指纹，解压全部文件，双击 `Install-CPCloud-Trust.cmd`。
3. 在 Windows 根证书确认弹窗中核对 **CPCloud Internal Root CA 2026** 并确认，然后重新打开浏览器访问 HTTPS 网站。

安装只作用于 `Cert:\CurrentUser\Root`，无需管理员权限。Windows 禁止后台无交互导入根证书，本次后台尝试返回 `UI is not allowed in this operation`；当前电脑的根证书信任未被自动安装。用户需要执行上面的交互式安装。撤销时双击同包的 `Remove-CPCloud-Trust.cmd`，仅删除指纹匹配的这一张根证书。

CA 证书 SHA256（DER）：

```text
D25FE092B5715FA19C6C21D77F0513B790006C7F78F37D003CAAD4CD6CF730DC
```

安装脚本内置该 SHA256 校验；证书被修改时会在访问证书存储前退出。安装包仅含公开 CA、安装/撤销脚本和说明，不包含私钥、密码、令牌或服务端配置。通过未加密 bootstrap 获取时，应使用本次交付文件或管理员独立提供的指纹核验。

其他客户端可以单独指定 CA，无需关闭证书校验：

```bash
curl --cacert cpcloud-root-ca.pem https://10.72.63.42:64022/api/health
```

Python 可以设置 `SSL_CERT_FILE` 指向 CA PEM；下载的 SSH 工具使用标准 TLS 校验。普通原生 SSH/SFTP 不依赖网站证书，原入口和 SSH 主机指纹不变。

## 实施内容

- HAProxy 在现有 TCP 22 listener 上识别 TLS ClientHello，透传到 Nginx `127.0.0.1:8443`，继续使用 PROXY v2 传递来源信息。HTTP 与 TLS 均保留原 `10.240.0.0/16` 来源范围；原 SSH 分支继续转到 `127.0.0.1:2222`。
- Nginx 启用 TLS 1.2/1.3，关闭 session tickets，终止外部 TLS，继续代理 API、Jupyter 和 WebSocket。HTTP 仅保留公开证书 bootstrap 目录，其他路径跳转 HTTPS。
- 新增 `PUBLIC_HTTPS_ENABLED`，将外部链接协议与集群内部 Ingress TLS 分开。线上设置该项为 true，内部 `INGRESS_USE_TLS` 保持 false。新旧实例指向当前入口的 Jupyter 链接动态使用 HTTPS，不修改已冻结的工作负载配置或 Kubernetes 路由。
- CORS 更新为 HTTPS 公共来源。Nginx 提供正确的 `X-Forwarded-Proto`，下载的 SSH 工具默认地址也变为 HTTPS。
- 生成独立内部 CA 和仅含 `IP:10.72.63.42` SAN 的服务端证书。CA 私钥位于 root 专有运维目录，服务端私钥位于 `/etc/cpcloud/tls/`，权限 0600；不加入源码包或公开下载目录。

最终 release：`20261017-https-fa4b01830e80`；此前 release 为 `20261017-tf-training-eb187b5829a2`。本轮仅修改后端访问配置、链接生成与测试文件，无前端重新构建、数据库迁移或计算节点重启。

## 续期与回退

网站证书有效期 397 天，本次续签后的到期时间为 **2027-11-18 06:45:35 UTC**。内部 CA 有效期五年，CA 更新时需重新分发客户端信任包。

`cpcloud-tls-renew.timer` 每日检查，剩余不足 45 天时签发新网站证书，验证 CA、IP、serverAuth 后原子替换并 reload Nginx。续期保留 CA 和服务端密钥；失败会恢复原网站证书。CA 剩余有效期不足以覆盖新网站证书时拒绝签发，要求管理员先更新 CA。

已用 `--force` 实际验证续期路径：网站证书序列号改变，CA 指纹保持不变，Nginx reload 后外部 TLS 校验仍通过。日常检查 service 也已执行成功。

操作命令：

```bash
systemctl status cpcloud-tls-renew.timer
journalctl -u cpcloud-tls-renew.service
sudo python3 /usr/local/sbin/cpcloud-tls-renew --force
```

上线前保存 HAProxy、Nginx、后端环境文件和旧 release 指针，并启用 20 分钟自动回退。外部 TLS、Jupyter、SSH 与浏览器验证通过后提交部署并取消自动回退。手动回退脚本保留：

```bash
sudo python3 /home/system/cpcloud-operations/https-20261017/rollback.py --force
```

脚本检查当前 release，防止覆盖后续其他部署；仅恢复此轮配置与指针，不恢复旧数据库或用户目录。若以后已切换其他 release，应由管理员按当前状态处理，不能绕过该检查。
