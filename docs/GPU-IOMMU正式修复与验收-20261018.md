## 持久化与保护范围

initramfs 中的 `00-cpcloud-gpu-domains` 在 udev/NVIDIA 模块加载之前执行，只处理经批准的 PCI 地址、NVIDIA 设备 ID 0x20f1 与类别 0x030200。验证八卡各自属于单设备 IOMMU 组、驱动尚未绑定和完整白名单后，逐组设为 identity；其他 PCI 设备不写入。

白名单 GPU 为 `0000:3d:00.0`、`0000:3e:00.0`、`0000:40:00.0`、`0000:41:00.0`、`0000:b1:00.0`、`0000:b2:00.0`、`0000:b4:00.0`、`0000:b5:00.0`。组编号通过 sysfs 动态读取，不固定为历史编号。

**identity 取消对应 GPU 的 DMA 地址翻译保护。** 这是用户已知并选择的取舍；不应把它描述成硬件 DMA 隔离完全保持不变。全局 IOMMU、网卡/存储等非 GPU 域、ACS、BIOS 和内核启动参数均未改动。既有 namespace、NetworkPolicy、IPv6 guard、权限和挂载边界继续保留。

只读服务 `cpcloud-gpu-domains.service` 在计算服务前核对八卡 PCI/UUID/索引、驱动绑定、identity 域及全部非 GPU 域。k3s-agent、worker、monitor 均通过 Requires/After 依赖它；检查失败时阻止执行服务和新的正常容量上报，SSH 可用于恢复。现场故意写入错误 UUID，已确认 k3s 和 monitor 的启动均被拒绝，恢复配置后服务正常。
