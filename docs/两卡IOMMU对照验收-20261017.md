# 两卡 IOMMU 对照验收（2026-10-17）

已完成用户授权的“允许两卡临时 A/B，测完恢复”。结论：**在本机当前驱动与 PCIe 拓扑下，将已测两卡从 DMA-FQ 改为 identity 后，P2P 数据正确性恢复；改回 DMA-FQ 后故障重现。** 这是映射/权限路径的正确性故障，不能只描述为吞吐瓶颈。

## 对照设计与实测

选用物理 GPU 6/7：`0000:b4:00.0`、`0000:b5:00.0`，分别属于独立 IOMMU group 29/30。仅切换这两个组，其他六张卡和所有非 GPU 设备域保持原值；未调整 ACS、驱动版本、内核、镜像或启动参数。

三轮使用同一个 CUDA 二进制，SHA256 为 `0085a35c849705c7d2a0937ac7fd997e21c6d6133e4f17273f9ca114c294a5c5`。在同一 TensorFlow 开发镜像中测试双向 256 B、4 KiB、8 MiB 拷贝，各重复三次。GPU 和 pinned host buffers 全程复用，每次更换图案并逐 uint32 验证目标数据。

| 阶段 | 两卡域 | P2P 数据正确 | 主机中转数据正确 | 本轮新增 DMA 故障 |
| --- | --- | --- | --- | --- |
| A | DMA-FQ | 0/18 | 18/18 | 有，GPU b5 写权限故障 |
| B | identity | 18/18 | 18/18 | 无 |
| A′（恢复后） | DMA-FQ | 0/18 | 18/18 | 有，同类故障重现 |

A/A′ 中 P2P CUDA API 返回成功，但每例的全部 uint32 数据错误，内核记录 `DMA Write NO_PASID`、`PTE Write access is not set`。B 中所有字均正确，测试窗口内没有新增 DMAR/Xid/AER 日志。错误数据的拷贝耗时不能作为有效吞吐性能结果。

现场原本已启用 DMA-FQ、`CONFIG_IOMMU_DEFAULT_DMA_LAZY=y`，启动日志确认 lazy invalidation。因此，延迟失效与复用现有 CUDA buffer 均不足以消除此故障。本次没有测试修改 NVIDIA 驱动的批量建立映射实现，也没有证明所有开启 IOMMU 的环境都会出错。

## 维护与恢复

维护前确认没有申请、实例或 GPU 计算任务，按资源池 → 节点的锁顺序切换数据库维护状态，cordon 节点并暂停 GPU 插件。保存并停止监控、worker 与 NVIDIA persistence 服务，确认无 NVIDIA 字符设备客户端后再逐卡解绑、切域与重绑。

B 测试结束立即恢复两卡 DMA-FQ，再执行 A′。恢复后核对八张卡的原始索引、UUID、PCI 地址与 NVIDIA 驱动绑定；其他六卡及非 GPU 域未改变。随后恢复原服务、GPU 节点标签、设备插件、调度及数据库 ONLINE 状态。

最终检查通过：

- 八张 GPU 全部为 DMA-FQ，8/8 可用，Kubernetes Ready、可调度且报告 8 张可分配 GPU。
- `k3s-agent`、monitor、worker、NVIDIA persistence 与计算节点 IPv6 guard 均 active；控制节点 guard 正常。
- NetworkPolicy 摘要仍为 `ec3022b7978278e09c9fe43da61b4c54a853575681de8d8a4dd9d1a83759f814`，租户隔离节点标签保留。
- HTTPS 首页和 `/api/health` 返回 200，使用平台 CA 验证证书，后端及数据库 healthy。
- 临时诊断容器退出且已移除；没有写入用户 `/data`、重启或持久化修改 IOMMU 配置。
- 当前 release 仍为 `20261017-isolation-bcd6e5ce03d9`，站点 NCCL 软件兼容配置继续启用。

## 正式修复的边界

GPU 专用 identity 配置已成为有现场证据支持的修复候选，但它降低对应 GPU 的 DMA 地址翻译保护。本次按授权恢复原状态，**没有上线八卡原生 P2P 修复**。

若选择正式使用此路线，仍需确定 DMA 隔离取舍，验证八卡全部 56 个有向拷贝组合、PyTorch 默认 NCCL、TensorFlow 单进程 MirroredStrategy、训练与 checkpoint、重启持久化及恢复行为，验收后才可撤销站点兼容回退。两卡 CUDA 结果不能替代这些验收。

原始记录位于 `.ops/p2p-ab-20261017/`：`compute-final.json` 包含三轮逐例数据、域切换记录及内核日志，`control-final.json` 和 `summary.json` 保存恢复与健康检查结果。可重复校验器源码为 [diagnose_dma_paths.cu](../deploy/gpu-peer/diagnose_dma_paths.cu)。
