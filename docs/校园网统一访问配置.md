# 校园网统一访问配置

2026-10-15，用户要求平台对当前电脑所在网段的所有用户提供统一网址，仅允许该网段访问，不要求每个用户建立 SSH 隧道。

## 允许网段与实际状态

Windows 路由查询显示，到 SSH 入口 `10.72.63.42` 使用 WLAN：本机地址 `10.240.52.192`，PrefixLength 为 16，掩码为 `255.255.0.0`。因此本轮按用户要求采用 **10.240.0.0/16**，覆盖 `10.240.*.*`。以太网的 `192.168.1.3/24` 为 Tentative，且不承载本次节点访问，未用作平台允许网段。

控制节点只有后端网段地址 `192.168.24.64/24`，默认网关 `192.168.24.254`；`10.72.63.42` 不在控制节点网卡上。本次 SSH 连接在节点上看到来源 `10.240.52.192`，说明该 SSH 入口保留了本次客户端来源地址；未来 Web 映射是否保留来源，仍需实际验证。

Nginx 已提供统一前端和 `/api/` 反向代理，监听 `192.168.24.64:8080` 和本机 `127.0.0.1:8080`。后端仍只监听 `127.0.0.1:8000`。新增规则：

```nginx
allow 127.0.0.1;
allow 10.240.0.0/16;
deny all;
```

127.0.0.1 仅保留节点健康检查、内部服务和已认证管理员的本机运维访问，不是向其他网络开放的浏览器入口。没有配置任意来源的 real-IP 信任，访问规则按实际连接来源判断，客户端不能通过伪造 X-Forwarded-For 绕过。

已实测：计算节点 `192.168.24.63` 访问首页、API 健康、登录路径及静态资源路径均为 403，附带伪造的 `X-Forwarded-For: 10.240.52.192` 仍为 403；节点本机健康检查和管理员本机访问正常。外部允许网段经统一网址登录尚未验证，因为网关 Web 映射信息尚未提供。

## 网关待配置的一条映射

以下是给网络管理端的具体需求，不是已执行的网关配置。外部端口尚未分配，使用明确占位项，不猜测其他节点现有端口用途。

| 配置项 | 要求 |
|---|---|
| 可达入口 | 10.72.63.42，或网络管理员提供的校园网反向代理入口 |
| 协议 | TCP / HTTP |
| 外部端口 | REPLACE_CONFIRMED_WEB_EXTERNAL_PORT；须确认未被占用 |
| 允许的用户来源 | 10.240.0.0/16 |
| 内部目标地址 | 192.168.24.64 |
| 内部目标端口 | 8080 |
| 源地址处理 | 优先 DNAT 并保留真实客户端来源 |
| 其他网段 | 拒绝访问此 Web 映射 |
| 现有 SSH 映射 | 保留 64022、63022，不修改 |

配置成功后统一网址为：

```text
http://10.72.63.42:REPLACE_CONFIRMED_WEB_EXTERNAL_PORT
```

所有允许网段内的用户使用该网址和自己的平台账号登录，不建立个人隧道。只发布 Nginx Web 入口；MySQL、Redis 和后端原始端口不需要映射。

如果网关必须改写来源为网关地址，Nginx 的当前规则会拒绝这个来源。此时应在网关按原始来源执行 10.240.0.0/16 限制，或使用已确认且仅可信代理可设置的来源传递方式，再相应调整节点配置。不得简单允许全部来源或信任用户随意提交的请求头。

## 完成映射后的验收

1. 从当前电脑通过统一网址访问首页、JS/CSS 和 `/api/health`，核实请求确实到达新控制节点。
2. 在控制节点访问日志核对实际来源是否仍为 `10.240.*.*`，完成允许网段管理员及普通用户登录验证。
3. 从允许网段之外验证连接被网关拒绝或 Nginx 返回 403，不能用只读配置检查代替这个实测。
4. 确认具体网址后同步部署文档、CORS 和适用的对外链接配置。后续 Jupyter/实例访问仍须结合 GPU 实例实际部署验收。
